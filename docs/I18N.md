# I18N.md — bilingual Vigie (FR default, EN mirror)

Status: **engineering spec, Phase 0**. French is the default and the version
that prevails. English is a mirror of Vigie's own words, never of publisher
text. Companion: `docs/EVENTS.md` (labels are built from the tables below).

## 1. URL scheme

| Surface | French (default) | English |
|---------|------------------|---------|
| front door | `/` | `/en/` |
| events index | `/evenements.html` | `/en/evenements.html` |
| one event | `/evenements/<event_id>.html` | `/en/evenements/<event_id>.html` |
| registre, mémoire, partir, affiche | `/registre.html` ... | `/en/registre.html` ... |
| method pages | `/methode/<slug>.html` | `/en/methode/<slug>.html` |
| Markdown twin | `/index.html.md` | `/en/index.html.md` |

Rules:

- `en_path = "/en" + fr_path`. Path segments stay French: they are
  identifiers, not prose, so no slug table can drift and no label edit breaks a
  link.
- Machine files are not mirrored: `llms.txt` (one file, lists both trees),
  `delta/*.json`, `registre/*.json` and `evenements/latest.json` are
  language-neutral (codes) and carry `{fr, en}` labels where a label exists.
- `<html lang="fr-CA">` / `<html lang="en-CA">`.
- Every page that has a counterpart carries, in both languages:
  `<link rel="alternate" hreflang="fr-CA" href="https://vigieqc.com/…">`,
  `hreflang="en-CA"`, and `hreflang="x-default"` pointing at the French page.
  A page without a counterpart emits no alternate.
- `rel="canonical"` is self-referential per language (the EN page is canonical
  for EN), never cross-language.
- `sitemap.xml` lists both with `xhtml:link` alternates; `stage_public` blocks a
  release when an hreflang target is missing (diagnosed, never silent).
- New paths need CSP entries in `vercel.json` (same strict `script-src 'self'`).

## 2. Language choice

- No redirect, no cookie, no `Accept-Language` negotiation, no geolocation.
  Static, cache-safe, crawler-safe, and French stays the door everyone enters.
- Every page header carries one link to its counterpart: "English" on FR pages
  (`lang="en"`), "Français" on EN pages (`lang="fr"`).
- The choice is not remembered. A reader who wants English bookmarks `/en/`.

## 3. Item language and chips

- An item's language is the **declared** `language` of its source in
  `sources.yaml`. It is never guessed per item. A cheap stopword check may flag a
  mismatch in the ops log (`language_check: mismatch`); the page still shows the
  declared value.
- Chip per member row: `FR` or `EN`, with visually hidden full text
  ("article en français" / "article in English"), never colour alone.
- Event chips: `FR + EN` when both languages cover it; "Couverture anglophone
  seulement" / "English coverage only"; "Même propriétaire" / "Same owner" on a
  language pair from one owner group (`docs/EVENTS.md` section 11).
- Publisher text in the other language is wrapped with its own `lang`
  attribute (`<span lang="en">` on a FR page), so screen readers switch voice.

## 4. What is translated, what never is

| Translated (by a human, reviewed by the founder) | Never translated |
|-----------------------------------------------|------------------|
| UI chrome (catalogue `fr.json`, `en.json`, same keys) | publisher titles, excerpts, quotes (R8) |
| event type and place labels (tables A and B) | author bylines, photo credits (R1/R2) |
| registre, mémoire, partir, affiche chrome | institution names, except the name the institution itself uses in English |
| method pages (`/en/methode/…`), each stamped "Translation. The French version prevails." | sealed records (codes only, language-neutral) |
| `docs/CHARTE.md` (both versions are drafted together) | URLs, ids, seals |
| dates and numbers formatting | anything Vigie did not write |

- No machine translation is shipped. Vigie does not set `translate="no"` on
  publisher text: a reader's own browser tool is the reader's act (decision to
  confirm, section 7).
- Formatting is hand-written and deterministic (no `locale` module, which
  depends on the OS): FR `6 octobre 2026`, `1 234,50 $`, `14 h 05`;
  EN `October 6, 2026`, `$1,234.50`, `2:05 p.m.`. Time zone `America/Toronto`
  via the existing fixed-offset helpers.
- English names: "Québec City" for the city, "Quebec" for the province
  (federal Translation Bureau usage; confirm).
- A key missing in `en.json` fails the test suite; it never falls back silently.

reworded; a reword never changes a code. Adding a code is a method change

## 6. Accessibility (self-imposed target: WCAG 2.2 AA)

- `lang` on `<html>` and on every span of the other language (WCAG 3.1.1, 3.1.2).
- Chips and classes carry text, never colour alone; contrast checked by the
  existing design-law tests in both themes.
- The language link is a real link, keyboard-reachable, first in the header
  after the skip link.
- Pages stay complete without JavaScript (current house law).

## 7. Risks to confirm with a Quebec lawyer

Listed as risks, not conclusions. Vigie is a non-commercial individual project;
whether the following apply is precisely what needs confirming.

1. **Charter of the French Language (as amended in 2022).** Whether Vigie is an
   "enterprise" whose website falls under the publication rules (section 52 and
   related). Design holds either way: French is the default, the EN tree never
   carries anything the FR tree lacks, and EN is never more prominent or more
   available.
2. **Displaying English publisher items on French pages.** Showing a third
   party's English text verbatim, attributed and linked, inside a French page:
   confirm no translation duty attaches, since R8 forbids Vigie to translate.
3. **Place and institution names in English** (Old Québec, Province of Quebec):
   confirm usage against the Commission de toponymie for official names.
4. **Accessibility law.** Quebec's government web standards and the Accessible
   Canada Act appear not to bind Vigie; confirm, and keep WCAG 2.2 AA as a
   voluntary floor.
5. **Privacy (Law 25).** No language preference or any personal data is stored;
   confirm the no-cookie, no-redirect design needs no notice.

Founder decisions: the `translate="no"` choice (section 4); "Québec City" vs
"Quebec City" spelling in EN; whether method pages ship in EN all at once or
page by page (each EN page must be complete before it is linked).
